VPN al SQL Server del banco: solo metadatos

RELOJ 1:30–1:50 (20 s, ~50 palabras) · [Integrante 3]. Todo está desplegado en AWS con Terraform: web, API y un SQL Server con datos ficticios en Fargate, y Claude Sonnet en Bedrock, que también describe el catálogo que arma el agente de esquemas. Son diez servicios. Otros agentes, como Kiro, usan las diez herramientas MCP. En producción, la misma imagen se conecta por VPN al SQL Server del banco. Vamos a la demo. PARA PREGUNTAS: los diez servicios son VPC, ALB, ECS Fargate, Bedrock, EventBridge, ECR, Secrets Manager, KMS, CloudWatch y SNS. Diferencias del demo con producción: tarea con IP pública en lugar de subredes privadas con VPC endpoints; ALB por HTTP limitado a la IP del equipo en lugar de interno con HTTPS; SQL Server Express con datos ficticios en lugar del SQL Server del banco por Site-to-Site VPN; el catálogo se arma desde Administración → Descubrir esquemas, mientras que en producción lo refresca cada noche un Builder lanzado por EventBridge Scheduler. En el demo EventBridge avisa si la tarea se detiene. Todo está en el mismo Terraform (deploy/aws).
